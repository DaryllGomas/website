01The problem

Nine to-do files, and no one place to look.

Tasks lived in plain text: seven division task files, an attention file and a separate command board. Earlier tries at the same idea (an AI agent, a separate status page, a cockpit) added more places, not fewer.

A checkbox in a text file can be ticked by anyone, at any time, with no proof. And as more AI sessions helped with the work, each one needed a safe way in that kept it to its own part.

"Unifying and harmonizing and symbiosis … it won't break things, it won't leave things behind."

02What I built

One control plane, six boards, narrow doors for agents.

  • Life Control, the one page: one NOW card, then sends, decisions, next and waiting. A "Done today" panel shows the evidence for each task closed.
  • Walled boards. Life is the top level; business, studio, tech, trading and education work each get their own board, so work never shows up in life's Now, Next or Today.
  • Done needs evidence. The API rejects blank or very short evidence, and the database rejects blank evidence. The habit is a commit, a link or a receipt.
  • Narrow doors for AI. Sessions use a small CLI; Hermes and the Slack bot use narrow tool bridges. The CLI and the eight-tool bridge have no delete or archive command.
  • Plans inside the page. Each project's plan opens inside Life Control, view-only, with no scripts allowed to run.
  • Slack briefs. A plain-text morning brief, and a ping when a new decision is waiting. No AI model in the loop.

It replaced the text files: on 5 Oct 2026 every open line was imported (583 rows) and eight Drive files were retired, with the originals kept.

03How it works

The life of a task: asked, worked, closed with evidence, kept.

1 · Ask

  • Me, on the page: quick add or the task panel
  • An AI session, through the CLI
  • Hermes, through its eight tools
  • The household bot: its own short list of routes

2 · Doors

  • The CLI names a board on every change; a mismatch is refused
  • The CLI refuses a task with no next action or no done-when
  • No SQL, no shell: predefined routes only

3 · Work

  • FastAPI on SQLite, plus a separate AI runner
  • One NOW, then sends, decisions, next, waiting
  • Normal task actions are recorded as events

4 · Close

  • Done needs evidence, or the server answers 400
  • A database CHECK backs it up
  • Defer needs a date and a reason; blocked needs a reason

5 · Keep

  • No delete or archive in the CLI or the task bridge
  • A task with a recorded send is never deleted
  • Reopening clears the evidence; nightly backup keeps 14

What the bridge can't do

No SQL, no shell, no routes of the caller's choosing: the tools use predefined Life OS routes. Who it acts as comes from its settings, not from the model. A real email needs a matching preview token, valid for 15 minutes.

06How it's tested and run

The rules are enforced, not hoped for.

  1. Evidence, enforced twiceThe API rejects blank or very short evidence, and a CHECK in the database rejects blank evidence, even from a stray UPDATE.
  2. Walls checked inside the writeWhen a caller sends the board it expects, closing a task checks it in the same transaction and a mismatch is refused. The CLI and the Hermes tools send it.
  3. The full suite, by ruleProject rule: the full suite before commits and deploys. 1,046 tests passed on 1 Nov 2026, across 30 test modules and one integration script: the API, the evidence rule, the walls, security, the CLI, the briefs, the Hermes and household bridges, migrations and the page.
  4. A second AI reviewsCodex is the independent reviewer. The walled boards went through six Codex rounds, ending in SHIP.
  5. Secure by defaultIt won't start on a network address without a login. bcrypt passwords, cross-site writes refused, a strict content policy, nothing cached.
  6. Integrations, kept narrowIt connects to AI providers, Hermes, and calendar, Drive and mail helpers. Each bridge exposes only its own short list of operations.
  7. Backed upA nightly backup at 3:30 AM keeps the last 14. Project rule: a manual backup before each deploy.
