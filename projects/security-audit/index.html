01The problem

A scan only helps if the owner can act on it.

A small office needs to know what is on its network and where the worst holes are: open ports, weak sign-ins, services with no password, what the internet can already see.

The person who approves the fix is usually not technical. A raw scanner dump doesn't reach them.

"What's on the network, what's here, and what are the worst holes … an executive summary, because you're going to be bringing this to people who are not technical."

02What I built

Two read-only sweeps, one report.

  • Linux sweep (Python, standard library only). Checks the perimeter, the machine it runs on, the local network and the public identity. Never logs in, sends no passwords, needs no root, changes nothing.
  • Windows sweep (the older PowerShell version). The same network checks, plus Windows endpoint checks: firewall profiles, disk encryption, antivirus, accounts, remote desktop, SMB.
  • Report builder (Python). Reads a run file from either sweep and writes one branded report: verdict, findings by severity, a numbered fix for each, and an optional "since last time" section.
  • A public sample for a fictional dental office, so the format can be shown without exposing a real network.
Which tool does what

The sample's endpoint findings (SMB1, BitLocker, antivirus, remote desktop, accounts) are Windows checks. The Linux sweep does not run them; the Windows sweep does.

Both sweeps write the same run-file shape, so one report builder reads either. Porting the Windows endpoint checks to the Linux sweep is not done yet.

2 · Score

  • Every finding gets a severity and an ID
  • Sorted worst first
  • Critical: fix today. High: this week. Medium: this month.

3 · Save

  • One JSON run file: findings, counts, evidence
  • Never overwritten: each run keeps its own file
  • What couldn't be checked is listed, not hidden

4 · Report

  • Each finding ID maps to a numbered fix and its action
  • One self-contained HTML file: no outside requests
  • Refuses to overwrite an earlier report

5 · Fix & re-scan

  • Fixes follow numbered procedures, each with its own check
  • Next run compared with the last: fixed, still open, or can't check
  • Plus a then-to-now scoreboard and what's new

06How it's tested and run

Safe to run, honest about its limits.

  1. Permission firstField work needs written permission from the owner of the network and devices before any scan.
  2. Read-only by designNo logins, no passwords sent, no root, nothing changed. SSH is asked which sign-in methods it allows, and that's all.
  3. Nothing overwrittenEach run writes its own file, and the report builder refuses to replace an earlier report.
  4. Unknown is not "fine"Checks it couldn't make are listed as unverified. In a comparison, items the new run can't see are marked can't-check, never fixed; a service that stopped answering is flagged to confirm, not counted as secured.
  5. Expected alarmsThe sweep trips intrusion detection. The report says so: an alert that matches a run is expected; one that doesn't should be investigated.
  6. Used on my own network firstThe Linux sweep was built to re-run my own audit and compare it with an earlier run. Those reports stay private.
